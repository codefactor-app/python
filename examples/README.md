# Конфигурация Codefactor для Python

Выберите профиль и сохраните его в своём проекте. Все YAML самостоятельные: дополнительные файлы для `include` не нужны.

| Профиль | Для чего подходит |
| --- | --- |
| [minimal.yaml](config/minimal.yaml) | Выбрать язык и использовать остальные настройки по умолчанию |
| [medium.yaml](config/medium.yaml) | Задать исключения, основные и структурные пороги, зависимости и кеш |
| [maximum.yaml](config/maximum.yaml) | Настроить дополнительные метрики, слои, наборы и отдельные пороги для участков проекта |
| [django.yaml](config/django.yaml) | Проект на Django: исключения `migrations/`, `settings`, слои `views → services → models`, ORM, почта, кеш и Celery во внешних вызовах |
| [fastapi.yaml](config/fastapi.yaml) | Сервис на FastAPI: исключения `alembic/`, слои `api → services → repositories → models`, httpx, SQLAlchemy и Redis во внешних вызовах |

Профили `minimal`, `medium` и `maximum` не привязаны к фреймворку и подходят любому проекту на Python. Профили `django` и `fastapi` берут за основу `medium` и добавляют каталоги, слои, переопределения порогов и внешние вызовы стандартной раскладки фреймворка; модуль или каталог, которого нет в проекте, просто не даёт совпадений.

## Применить профиль

Если пакет установлен, скопируйте профиль из его каталога:

```sh
cp .venv/share/codefactor/examples/config/medium.yaml analyzer.yaml
```

Путь рассчитан на виртуальное окружение `.venv`. В другом окружении ищите `share/codefactor/examples` внутри его каталога. Если пакет ещё не установлен, сохраните YAML по ссылке из таблицы.

Из корня анализируемого проекта:

```sh
codefactor config check --file analyzer.yaml --strict
codefactor scan . --config analyzer.yaml --strict-config
codefactor config show --file analyzer.yaml --resolved
```

## Адаптировать под свой проект

- `languages.enabled` определяет языки анализа; пакет поддерживает все пять языков Codefactor.
- `paths.include: ["**"]` включает поддерживаемые файлы, в том числе файлы в корне. Средний и расширенный профили исключают тесты, сгенерированный код и типовые артефакты. Уберите нужные исключения, если хотите анализировать эти файлы.
- Правила `.gitignore` также учитываются. Зависимости выделены через `vendor.paths`, чтобы изучать их связи отдельно от метрик проекта.
- Globs чувствительны к регистру и считаются от корня анализа: `**/test_*.py` и `**/*_test.py` покрывают оба соглашения pytest.
- `limits` задаёт уровни предупреждений `warn` и ошибок `error`. Подберите пороги для своего проекта, затем проверьте их через `config check --strict`. `limits.by_language` нужен только проектам с несколькими языками: для единственного языка он молча перекрывает общий порог.
- Модели Django, class-based views, ModelAdmin и репозитории по замыслу содержат независимые методы, поэтому профили фреймворков поднимают для них `lcom4`, `methods_per_class` и `function_params` через `limits.by_path`.
- Правила `external.rules` начинайте с `*`: внутри пакета с `__init__.py` движок дополняет имя импорта именем пакета, и точный шаблон `requests.post` не совпадает. Методы клиентов распознаются через типизированный атрибут или параметр; объект, созданный в той же функции, до класса не разрешается.
- В расширенном профиле и профилях фреймворков пути слоёв, полные имена сущностей, сторонние библиотеки и каталоги старого кода — примеры для замены. `architecture.composition_roots` действует, только если файл сборки попадает в селектор слоя.

Минимальный профиль сохраняет архитектурный и алгоритмический анализ по умолчанию. `scan .` автоматически находит `analyzer.yaml` или `analyzer.yml`; для `scan ./src` передавайте файл явно: `--config analyzer.yaml`. После изменения YAML перезапустите локальный веб-интерфейс.

Добавьте `analyzer.yaml` в репозиторий проекта, а `.analyzer-cache/` — в `.gitignore`.

## Контроль структуры в CI

Архитектурные находки `arch_cycle` и `arch_boundary` не меняют код завершения даже с `--fail-on-warn`. Для блокировки используйте числовые пороги: `limits.module_cycle: {warn: 0}` в `medium`, `django` и `fastapi` превращает цикл между модулями в предупреждение, которое останавливает проверку с `--fail-on-warn`; `{error: 0}` в `maximum` даёт код завершения `2` без флага. Нарушения запрещённых зависимостей между слоями читайте из отчёта `--format sarif` или `--format json`.
